# تكسي العراق — موقع GitHub

موقع مستقل أُكمل من ملف t.js الجزئي. تم بناء واجهات الزبون والسائق والإدارة والتسجيل والملف الشخصي، وتطوير إجراءات الطلب إلى عمليات قاعدة بيانات مشتركة. الاسم الابتدائي المختار هو «تكسي العراق». يمكن تغيير الاسم داخل index.html وسياسة الخصوصية.

## الحالة الحالية

اختار صاحب المشروع ربط قاعدة البيانات لاحقًا. لذلك config.js يحتوي قيم الربط الفارغة عمدًا. يمكن استعراض الخريطة واختيار النقطتين والأجرة الافتراضية، ويظهر تنبيه أن الخدمة قيد الإعداد. إرسال الطلبات والتسجيل وتبادل البيانات يتفعّل بعد تنفيذ إعداد Supabase أدناه. لا تُنشأ طلبات وهمية على الجهاز، ولا يُعرض نجاح إرسال قبل تأكيد قاعدة البيانات.

## أولًا — الرفع إلى GitHub Pages

1. أنشئ مستودعًا عامًا جديدًا مثل iraq-taxi.
2. فك الضغط وارفع جميع محتويات مجلد taxi-github إلى جذر المستودع، مع مجلدات vendor وlicenses وdatabase.
3. اضغط Commit changes.
4. افتح Settings → Pages → Deploy from a branch → main → /(root) → Save.
5. انتظر نجاح النشر وافتح رابط Pages. يعمل الموقع من ملفات ثابتة دون خطوة بناء.

## ثانيًا — ربط قاعدة البيانات لاحقًا

1. أنشئ مشروع Supabase مستقلًا للتكسي. استخدم مشروعًا مخصصًا لهذا الموقع.
2. افتح SQL Editor وشغّل محتويات database/setup.sql كاملة. تنفَّذ داخل معاملة واحدة ويمكن إعادة تشغيلها مع الحفاظ على البيانات الموجودة.
3. من إعدادات API انسخ Project URL وPublishable key. ضع القيمتين في config.js ثم ارفع الملف المعدّل إلى GitHub.
4. config.js جزء عام من الموقع، ويحتوي المفتاح العام المخصص للمتصفح فقط. احتفظ بمفاتيح secret أو service_role خارج ملفات الموقع.
5. من Auth → URL Configuration أضف رابط موقع Pages في Site URL وRedirect URLs، بما فيه الشرطة النهائية لمسار المستودع، حتى تصل روابط تأكيد البريد واستعادة كلمة المرور للموقع الصحيح.
6. فعّل مزوّد البريد Email وكلمات المرور، وابقِ تأكيد البريد مفعّلًا. للاستخدام الفعلي مع عدد مستخدمين، اضبط SMTP مخصصًا وحدود الإرسال من إعدادات Auth.
7. سجّل حسابك الشخصي بالموقع وافتح رسالة تأكيد البريد.
8. عدّل YOUR_ADMIN_EMAIL في database/make-admin.sql إلى بريد حسابك، وشغّل الملف من SQL Editor. هذه الخطوة تجعل حسابك إدارة، ثم أعد تسجيل الدخول لتظهر لوحة الإدارة.
9. جرّب بحساب زبون وحساب سائق من متصفحين أو جهازين مختلفين. اعتمد السائق من الإدارة، ثم يفعّل السائق استقبال الطلبات بالمحافظة نفسها.

setup.sql يمنح صلاحيات Data API اللازمة صراحة ويُفعّل RLS على كل الجداول. يضيف جداول الرحلات والملفات الشخصية ومواقع السائقين إلى supabase_realtime إذا كان النشر موجودًا. إذا لم تتوفر تحديثات لحظية، يوجد تحديث احتياطي كل 15 ثانية أثناء ظهور الصفحة.

## الوظائف

- تسجيل بالبريد وكلمة مرور مع الاسم والهاتف والمحافظة، أو حساب سائق مع السيارة واللوحة.
- تأكيد البريد واستعادة كلمة المرور وحفظ الجلسة. الرجوع بين الصفحات لا يسجّل الخروج، والخروج له زر مستقل.
- اختيار الانطلاق والوجهة على خريطة Leaflet/OpenStreetMap، أو اختيار الانطلاق بزر موقعي بعد إذن المستخدم.
- نوعا خدمة اقتصادي ومريح، وتسعيرات تديرها الإدارة. جميع المبالغ بالدينار العراقي.
- الأجرة تعتمد على مسافة مباشرة بين النقطتين وتُحسب مجددًا داخل قاعدة البيانات. السعر تقديري ويؤكده السائق والزبون قبل بدء الرحلة. القيم الافتراضية أُضيفت للتجهيز ويمكن تعديلها من الإدارة.
- طلب نشط واحد لكل زبون، ورحلة نشطة واحدة لكل سائق. حجز الطلب وتغيير حالته يتمان في معاملة مع قفل الصفوف وفهارس فريدة، لمنع استيلاء سائق ثانٍ أو تكرار الطلب عند إعادة المحاولة.
- حالات الرحلة هي بانتظار سائق، مقبولة، السائق وصل، جارية، مكتملة أو ملغاة.
- الزبون يستطيع الإلغاء قبل وصول السائق، والسائق قبل بدء الرحلة، والإدارة تستطيع إلغاء الرحلة النشطة.
- بيانات اتصال طرفي الرحلة تظهر للطرفين أثناء الرحلة النشطة. السائق المتاح يشاهد نقاط الطلب قبل القبول، وتتطلب الحسابات موافقة الإدارة.
- مشاركة أحدث موقع السائق اختيارية أثناء فتح الصفحة، ويراها زبون الرحلة النشطة فقط والإدارة. هذا الموقع لا يوفر تتبعًا في خلفية الجهاز أو إشعارات دفع خارج المتصفح.
- حصيلة الرحلات المكتملة وإحصاءات اليوم بحسب توقيت بغداد. المؤشرات تمثل الأجور المسجلة التقديرية، ولا تتضمن خصم مصروفات أو عمولات.
- لوحة الإدارة لاعتماد السائقين وإيقاف اعتمادهم ومراجعة الطلبات وضبط التسعيرات واستقبال طلبات حذف الحساب.

## معالجة طلبات حذف الحساب

زر طلب الحذف يسجل الطلب للإدارة ويخبر المستخدم أنه بانتظار المراجعة. يُعالج مالك الخدمة الطلب من لوحة Supabase بعد التحقق من صاحب الحساب ومراجعة الرحلات المشتركة المرتبطة به. علاقات قاعدة البيانات تمنع حذف ملف مستخدم ذي رحلات مرتبطة مباشرة، لذلك يلزم ترتيب حذف أو إخفاء الهوية في السجلات المرتبطة وفق سياسة الخدمة ثم إزالة حساب Auth وإيقاف جلساته. طلب الحذف لا يعني تنفيذ الحذف آليًا في هذه النسخة.

## الفحص قبل التسليم

فُحصت واجهة الخريطة واختيار النقطتين وحساب التقدير ونافذة التسجيل وحقول السائق في المتصفح. اجتازت ملفات JavaScript فحص الصياغة. اختُبر ملف SQL محليًا بمحرك PostgreSQL عبر PGlite مع محاكاة هوية Auth، وشملت الاختبارات صلاحيات الأدوار وخصوصية الرحلات وتسعير الخادم ومنع التكرار وتسلسل حالات الرحلة. لم تُربط هذه النسخة بمشروع Supabase فعلي بعد؛ اختبار جهازين والبريد وRealtime مطلوب بعد الربط.

## محتويات المجلد

- index.html وstyles.css وapp.js لواجهات الموقع ودواله.
- config.js لعنوان المشروع ومفتاحه العام.
- database/setup.sql للجداول والصلاحيات وعمليات الرحلات، وmake-admin.sql لتعيين حساب الإدارة بعد التسجيل.
- privacy-policy.html للسياسة وطلب حذف البيانات. حدّث جهة التواصل والاحتفاظ عند تشغيل الخدمة فعليًا.
- vendor لمكتبات Leaflet 1.9.4 وSupabase JS 2.95.3 المضمّنة، وlicenses لتراخيصها.

الخرائط والاتصال والحسابات تحتاج إنترنت. عند انقطاع الشبكة يُبلّغ المستخدم، ولا يُعد الطلب مرسلًا حتى يرد تأكيد الخادم. هذا الإصدار يستعمل تحديثات داخل الصفحة ولا يدّعي وصول إشعارات دفع والهاتف مغلق.
